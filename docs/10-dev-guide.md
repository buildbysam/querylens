# 10. Development Guide

## 10.1 Project Structure

```text
.
├── compose.yaml, Dockerfile, .dockerignore
├── drizzle/                       # generated SQL migrations
├── drizzle.config.ts
├── public/css/styles.css          # generated by Tailwind (dev)
├── scripts/
│   ├── build.js                   # legacy tsc build (see §10.8)
│   └── create-admin.js            # creates a user account (plain Node, no build)
└── src/
    ├── index.ts                   # process entry: server, scheduler, sampler, shutdown
    ├── app.ts                     # createApp(): middleware + routes, no side effects
    ├── config.ts                  # environment loading and validation
    ├── global.css                 # Tailwind entry + base styles
    ├── types.ts                   # Hono context variables
    ├── modules/
    │   ├── auth/                  # /login, /auth/login, /auth/logout
    │   ├── collector/             # views, service, scheduler, in-memory status
    │   ├── databases/             # /api/databases
    │   ├── health/                # checks, sampler, /health
    │   ├── pages/                 # page compositions + error template
    │   └── snapshots/             # /api/views, /api/snapshots*
    └── shared/
        ├── db/                    # schema, relations, connection pool
        ├── lib/                   # crypto, sessions, pg client, time
        ├── middleware/            # auth, csrf, errors, logger, rate limit, request id
        └── views/                 # layouts/ and components/
```

## 10.2 Module Responsibilities

| Module         | Responsibility                        | Public surface                                                                                                                                 |
| -------------- | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Authentication | Sign-in and session handling          | `auth` router                                                                                                                                  |
| Databases      | Registration and connectivity testing | `databasesApi`, `listDatabases()`, `testConnection()`, `registerDatabase()`                                                                    |
| Collector      | Scheduled collection and storage      | `startScheduler()`, `stopScheduler()`, `resumeScheduler()`, `getSchedulerSnapshot()`, `createScheduler()`, `collectDatabase()`, `collectAll()` |
| Snapshots      | Read access to stored collections     | `snapshotsApi`, `listViews()`, `latestSnapshots()`, `recentSnapshots()`                                                                        |
| Health         | Platform checks                       | `health` router, `runHealthChecks()`, `sampleNow()`, `getLatestReport()`, `startHealthSampler()`                                               |
| Pages          | Server-rendered pages                 | `pages` router, page components                                                                                                                |

## 10.3 Scripts

| Command                                     | Description                                                          |
| ------------------------------------------- | -------------------------------------------------------------------- |
| `pnpm dev`                                  | Server with reload (`tsx watch`) plus the Tailwind watcher.          |
| `pnpm dev:hono`                             | Server only.                                                         |
| `pnpm typecheck`                            | `tsc --noEmit` over sources and scripts.                             |
| `pnpm create-admin --name "…" --email …`    | Create a user; prompts for the password (or reads `ADMIN_PASSWORD`). |
| `pnpm format` / `pnpm format:check`         | Prettier (with the Tailwind class-sorting plugin).                   |
| `pnpm exec drizzle-kit generate --name "…"` | Generate a migration from schema changes.                            |
| `pnpm exec drizzle-kit migrate`             | Apply pending migrations (needs `DATABASE_URL` in the environment).  |

## 10.4 Common Tasks

### Run locally

See [§3.4](03-setup.md#34-quick-start--local-development).

### Create a user

```bash
pnpm create-admin --name "John Doe" --email John@example.com
# non-interactive:
ADMIN_PASSWORD='S3cure!pass' pnpm create-admin --name "John" --email john@example.com
# inside Docker:
docker compose exec app node scripts/create-admin.js --name "John" --email john@example.com
```

### Add a collected view

Add an entry to `COLLECTED_VIEWS` in `src/modules/collector/views.ts`:

```ts
{
  name: "pg_stat_bgwriter",
  description: "Background writer statistics",
  sql: `SELECT * FROM pg_stat_bgwriter LIMIT ${MAX_ROWS_PER_VIEW}`,
  // optional: availabilityCheck: "SELECT … AS available",
}
```

No other change is needed: the view is collected, stored, offered by
`/api/views`, and displayed on `/app/snapshots`. Views that may be missing on
some servers should declare an `availabilityCheck` returning a boolean
`available` column.

### Add a feature module

1. Create `src/modules/<feature>/` with `routes.ts(x)`, `service.ts` and
   `types.ts`.
2. Add tables to `src/shared/db/schema.ts` and generate a migration, if needed.
3. Add the page under `src/modules/pages/`, composed from shared components.
4. Mount the router in `createApp()` (`src/app.ts`) — after `authMiddleware`
   unless it is public.

Confirm the feature is within the scope in [§1.2](01-overview.md#12-scope)
first.

## 10.5 Working with the Data Model

`src/shared/db/schema.ts` is the single source of truth. To change it:

```bash
# 1. Edit src/shared/db/schema.ts
# 2. Generate SQL (no database connection needed)
pnpm exec drizzle-kit generate --name "describe the change"
# 3. Review drizzle/<timestamp>_<name>/migration.sql
# 4. Apply
pnpm exec dotenv run -f .env.development.local -- drizzle-kit migrate
```

With Docker Compose, the `migrate` service applies pending migrations on every
`docker compose up`. Never edit a migration that has been applied anywhere; add
a new one.

| Covered    | Examples                                                                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Libraries  | Redirect sanitising, time formatting, script-safe JSON, credential encryption, error mapping, event log bounds                                                                 |
| Validation | Database input schema                                                                                                                                                          |
| Health     | Status aggregation, payload redaction                                                                                                                                          |
| Scheduler  | Interval, overlap prevention, failure handling, stop/resume, error window                                                                                                      |
| Views      | Component accessibility contracts, error-page variants, absence of hex colours                                                                                                 |
| HTTP       | Sign-in, CSRF, sessions and refresh-token reuse, databases API, collection → snapshots API → pages, unreachable databases, read-only enforcement, 400/401/403/404/429 handling |

## 10.6 Deployment

### Docker Compose

```bash
git pull
docker compose build
docker compose up -d          # runs migrate, then restarts app
docker compose logs -f app    # stdout is quiet in production; see the logs volume
```

Back up the `pgdata` volume (or your external metadata database) and keep `.env`
— especially `ENCRYPTION_KEY` — with it.

### Manual deployment

```bash
pnpm install --frozen-lockfile
pnpm exec tailwindcss -i ./src/global.css -o ./dist/public/css/styles.css --minify
export NODE_ENV=production   # plus every variable in §3.2
pnpm exec drizzle-kit migrate
node --import tsx src/index.ts
```

In production, static files are served from `dist/public`. Run the process under
a supervisor (systemd, a container runtime) that sends `SIGTERM` on stop:
QueryLens closes the HTTP server, waits up to 10 s for an in-flight collection,
closes the pool, and exits.

## 10.7 Known Limitations

| Limitation                  | Notes                                                                                                                                                   |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pnpm build` / `pnpm start` | `tsc` does not rewrite the `@/…` path aliases and emits to `dist/src/`, so the compiled output cannot run. Run with `tsx` (as the Docker image does).   |
| `LOG_LEVEL`                 | Validated but not applied.                                                                                                                              |
| Single instance             | Collection status, health history, events and rate-limit counters are in memory; running several instances would collect every database more than once. |
| Snapshot retention          | None; snapshots accumulate indefinitely.                                                                                                                |
| TLS to monitored databases  | Not configurable.                                                                                                                                       |
| Process output              | In production the logger writes only to files under `LOG_FILE_PATH`.                                                                                    |

## 10.9 Development Practices

| Practice              | Description                                                                                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Feature isolation     | Modules use each other only through exported functions, never internal state.                                                                |
| Thin pages            | Pages compose shared components and receive data from their route; no data fetching in JSX.                                                  |
| Tokens only           | Use Tailwind token utilities (`bg-surface`, `text-fg-muted`, …). No hex colours in JSX, no arbitrary values when a theme value can be added. |
| Server first          | Alpine.js only for the interactions listed in [§7.3](07-web.md#73-interaction).                                                              |
| Read-only monitoring  | Collection never modifies monitored databases.                                                                                               |
| Protected credentials | Credentials are stored encrypted and never logged or returned.                                                                               |
| Safe errors           | Throw `HTTPException` for client errors; let `onError` render the page.                                                                      |
